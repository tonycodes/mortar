## VoiceOver and keyboard checklist

Components: `MortarCommentComposer` and `MortarConversation` (bubbles, choice pills, failed-message Retry).

This agent cannot run VoiceOver, Full Keyboard Access, a hardware keyboard, or an iOS simulator. Items marked **human** are unverified. Items marked **automated** are asserted in the iOS simulator job once that workflow passes on the fix commit; they are still not a VoiceOver pass.

### Composer

- **Human.** Focus the field. Return inserts a line and does not send.
- **Human.** Command-Return sends the trimmed text and clears the draft, on a Mac and on iOS with a hardware keyboard.
- **Human.** An empty or whitespace-only draft keeps Send disabled, and Command-Return does not send.
- **Human.** While `isStreaming`, Command-. activates Stop, the draft stays editable, and Send is not shown.
- **Human.** While a reply streams, tab bar and sidebar navigation still work. The composer does not disable anything outside itself.
- **Human.** Attach, Send, and Stop are buttons named "Add attachment", "Send", and "Stop". The glyph is 32pt inside a 44pt target. Keyboard focus shows the 2pt focus ring on the field and on those buttons.
- **Human.** The error is in the field's accessibility hint, matching `MortarTextField`, and the border uses `danger`. The hint is hidden while an error is showing. VoiceOver should read the error after the field's name when the field is focused. It is not a live alert (`role="alert"` is the web field pattern; the Swift text field does not announce on appearance either).
- **Automated, then human.** `testComposerMaxLengthCutsAndCounts` sets `Hello, world` with `maxLength` 5 and expects the text `Hello`. `showsCount` is labelled "n characters left" in the view; a person should hear that with VoiceOver. The unit-test host did not expose that label.
- **Human.** `isFocused = true` moves focus into the field (the correction flow). `isFocused = false` dismisses the iOS keyboard. Focusing or leaving the field updates the binding. Not covered by an automated test that can run on this branch.

### Conversation

- **Automated, then human.** `testConversationVoiceOverReadsProse` checks `MortarChatSpeech.prose`, the text the bubble label uses: `Invoices include tax lines and billing-2026-11.csv. See the notes.` with no `**`, backticks, or URL. The simulator unit-test host did not publish SwiftUI accessibility elements (the walk was empty), so this does not prove the label is what VoiceOver speaks. A person should confirm that, and that the action named with the link title opens https://example.com.
- **Human.** Streaming with no text yet: the value is "Responding", and the dots are not a separate control. A streaming bubble that already has text speaks the prose so far and still reports "Responding".
- **Human.** Choice pills are buttons, reachable with VoiceOver and with the keyboard (Full Keyboard Access on iOS, Tab on Mac), with a visible focus ring. They are 32pt tall. The composer's icon buttons are 44pt (`MortarTokens.touchTarget`). The pills were not enlarged: that would change the recorded snapshots. Confirm the target or file a follow-up.
- **Human.** Failed Retry activates the retry closure.
- **Human.** Wide Mac window: the column stays at most 720pt and stays centred. Narrow window: the column uses the width it has and does not overflow. Mac snapshots for this exist; they run after the rebase.

### iOS keyboard and safe area

- **Human.** With the software keyboard open, the composer stays above it (`safeAreaInset` on the bottom edge) and is not covered. Messages scroll above the composer.
- **Human.** Dragging the message list dismisses the keyboard (`scrollDismissesKeyboard(.interactively)`).
- **Human.** The newest message stays in view as messages arrive and as a draft grows.
- **Human.** Large accessibility text does not clip the composer, the count, or a multi-line draft. An iOS snapshot variant exists (`testConversation` / `testCommentComposer`, `large-text`); look at the device, not only the image.
- **Human.** With the keyboard closed, the composer's bottom padding clears the home indicator.
